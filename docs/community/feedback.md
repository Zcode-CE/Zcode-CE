# 反馈与诊断

> 面向提交反馈的人与运维者：反馈都发到哪里、诊断信息包含什么、哪些内容会被脱敏。

ZCode-CE 的反馈链路**不经过任何官方服务**。用户在设置页「**反馈与诊断**」分区选择反馈渠道，
所有既有反馈入口（聊天错误横幅、任务菜单、帮助菜单、远程连接失败页等）统一走这份配置。

## 反馈渠道

| 模式                      | 行为                                        |
| ------------------------- | ------------------------------------------- |
| **本项目 GitHub**（默认） | 生成 Issues 预填链接，在系统浏览器中打开    |
| **自定义地址**            | 支持 `{title}` / `{body}` 占位符的 URL 模板 |
| **关闭**                  | 不提供反馈入口                              |

渠道配置保存在本机（`localStorage` 的 `zcode.feedback.*`），不跟随工作区切换，也不跨设备同步。

### 渠道不可用时的行为

渠道为「关闭」，或自定义地址为空 / 非法时，反馈入口**不会静默失败**：
它会打开设置页的「反馈与诊断」分区并提示原因，让用户能当场修正配置。

反馈入口是用户遇到问题时的唯一出口，点了没反应会被读作功能故障，因此这里选择显式引导。

## 为什么用预填链接

- **零凭证**：不需要 PAT 或 OAuth，不引入新的信任面
- **用户可见**：在浏览器里看到完整内容后才点提交
- **附件**：由用户在浏览器中手动附加，不需要我们实现上传通道

## 诊断信息范围

预填内容包含（**均可在提交前编辑**）：

| 包含                          | 不包含    |
| ----------------------------- | --------- |
| 应用版本 / 构建 ID / 构建时间 | deviceMid |
| OS / 架构 / Node 版本         | 账号标识  |
| 错误摘要（入口自动带入）      | 凭据      |
| 问题描述                      | 完整日志  |

诊断字段可在设置分区逐项勾选。日志附件可在「反馈与诊断」分区**本地导出**后自行附加。

## 从入口点进反馈时的上下文

从错误横幅、任务菜单或远程连接失败页点「反馈」时，入口会把你当时看到的内容
（可读错误摘要、任务标题与日志路径、最近的连接日志）**脱敏后**带进预填正文，
不需要手工再抄一遍。

入口上下文是一次性的：设置分区取用后立即清空，不会污染下一次反馈。

## 官方工单服务

「官方工单服务」在**自定义地址**模式下保留为显式入口，连的是官方反馈 API
（`feedbackService`，需要官方账号与设备标识）。

对社区版构建它通常不可用，因此**不参与默认路径**；保留它是为了不剥夺用户本应拥有的官方渠道能力。

## 安全约束

自定义 URL 模板只放行 `http:` / `https:` 协议，其余（`javascript:` / `data:` / `file:` / `vbscript:` 等）
一律拒绝，且**不产出任何半成品地址**。这条约束在入口侧与设置页共用同一条构造路径，有回归测试覆盖。
