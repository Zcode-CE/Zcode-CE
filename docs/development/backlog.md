# 长期欠账与有意不做

> **定位**：面向贡献者与外部读者的**长期方向**与**有意不做的决策**。
> 全量未完成细目（含代价、证据、排期）在维护者私有工作区维护，不在本文件重复 —— 本文件随能力变化原地更新。
> **完成项不留痕**：已落地能力由对应主题文档描述；历史见 git 与 release notes。

## 长期方向

| 方向                 | 现状与边界                                                                                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **远程控制连接面**   | 自托管 `?token` 形态可用；逐设备断开已落地。**设备级凭据吊销**未做（需要设备维度状态所有者，当前换令牌会让所有设备掉线）。                                       |
| **工作区可见性统一** | 服务端注册表 + 未启动态已落地；`workspaceTabs` 作用域模型仍与侧栏口径不一致（239 处引用），迁移需独立设计与回归。远端条目的多端可见性涉及安全边界，需独立 spec。 |
| **发布与分发**       | 单包 npm + 无头发行包 + AUR + Docker 本地构建可用；**npm 多包发布**（主包薄 + 平台载荷分包）未做。Docker 镜像**有意不发布**。                                    |
| **上游跟进**         | 以逐特性移植跟进开源基线（不整树 merge），遥测每次重新剔除；台账见 [上游同步](upstream-sync.md)。                                                                |
| **文档与合规**       | 公开文档只放当前事实与契约；一次性记录在私有工作区。许可材料的 `reviewRequired` 闭环仍未完成（上游材料本身不全）。                                               |

## 有意不做（写清原因，防后人误以为漏了）

| 条目                                                                      | 原因                                                                                                                                                                                      |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **云端 relay / 配对服务器 / 移动壳**                                      | 上游自 v3.15.1 起随开源版分发 relay **客户端**与 Android 壳（3.16.2 = Relay V2 + 账号登录 + 设备管理），但中继/配对**服务端**是闭源服务；本项目有意不引入中继，保持自托管 `?token` 形态。 |
| **Source Server 远端常驻进程 / 远程设备管理**（上游 3.16.2 F2/F5）          | 上游把「远端自己跑 + 设备注册表」做成一套 R3 架构（约 +37617 行 / 71 源文件 / 27 篇连接 UX 规约）。本项目远程工作区是窗口内 SSH/Docker 连接注册表、手机远控是自托管 `?token`，不引入远端 daemon、账号设备体系与配套中继。**用户 2026-10-29 裁定不跟进**；若将来要做，须先立独立安全设计（谁能启动 daemon、凭据归属、断线恢复语义），不能按上游整链照搬。 |
| **Bot Channel 的第三方渠道实现**（dingding / discord / wecom 等留位渠道） | 上游也只留位、无实现证据。                                                                                                                                                                |
| **README 的「更新至 vX」措辞**                                            | 那是官方仓库自己的更新日志，不是产品文档。                                                                                                                                                |
| **Docker 镜像发布**（`ghcr.io/<org>/zcode-ce-server`）                    | 维护与上传成本不值；仓库根 `Dockerfile` + `compose.yaml` 本地构建可用。                                                                                                                   |
| **`conversationRowSharing` 的 row pool**                                  | 全仓无独立消费方，搬了也只是死代码；待出现消费者再评估。                                                                                                                                  |
| **`stream-animate`（上游动画开发工具）**                                  | 全仓 0 运行时引用（独立 dev 工具），不复制、不打包。                                                                                                                                      |
| **拒绝用户用已有软件完成同类任务**                                        | 引擎选择权属于用户；本项目不强制视觉验证流水线，也不禁止 Word / WPS / Pages。                                                                                                             |

## 已知与上游的有意偏离（是决策，不是欠账）

| 项            | 我们的选择                    | 上游                                  | 原因                                                                                                                 |
| ------------- | ----------------------------- | ------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 飞书 SDK 版本 | **1.74.0**                    | 1.64.0                                | 1.64.0 的两个缺陷正好落在飞书唯一使用的长连接路径上：一个杀宿主进程、一个静默丢事件（1.74.0 已修）。                 |
| 手机远控形态  | **自托管 Web 控制**           | relay 客户端 + Android 壳 + IM 机器人 | 不引入中继；偏离在形态、不在「做不做」。Bot 服务端能力已与官方同步，默认关闭、用户同意后可用，两条路径以标签页共存。 |
| 遥测          | **移除**                      | 默认开启 ARMS RUM + OTLP              | 后台自动上报与本项目定位不符；保留下来的设备身份只承载计费头。见 [遥测与隐私](telemetry.md)。                        |
| Office 能力   | MIT 开源实现 + 自带 Node 载荷 | 官方闭源插件（禁商用）                | 许可不可分发；核心能力零外部依赖。见 [办公插件](office-plugins.md)。                                                 |
| Computer Use  | MIT `@trycua/cua-driver`      | 私有 helper 二进制                    | 许可与平台限制；Windows 正式支持、Linux 实验性。                                                                     |
