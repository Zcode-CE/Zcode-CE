# 欠账台账（Backlog）

> **用途**：唯一汇总处。任何"未做 / 排后续 / 有意不做"的东西都记在这里 —— 否则它会散落在 release-notes、分析报告、清单、issue 里，**然后被漏掉**。
> **建立原因**：2026-09-24 汇总本批欠账时发现它们散落在**四处**（release-notes 的已知限制、`.reverse/90-upstream-v3143/` 的建议序、`.reverse/45-release/CE3-CHECKLIST.md`、`.reverse/92-copy-format/`），**没有一处能看到全貌**。

## 记录格式

| 字段 | 含义                                                        |
| ---- | ----------------------------------------------------------- |
| 条目 | 要做什么（一句话）                                          |
| 类   | `正确性/安全` / `上游跟进` / `协议引擎` / `产品面` / `工程` |
| 来源 | 结论出自哪份报告或哪次决策                                  |
| 代价 | S / M / L                                                   |
| 风险 | 低 / 中 / 高（含"不做会怎样"）                              |
| 状态 | `待排` / `已排入 <版本>` / `有意不做（原因）` / `已完成`    |

**规则**：① **有意不做**必须写原因（否则后人会以为是漏了）；② 完成时**不要删行**，改成 `已完成` 并写落在哪个提交/版本；
③ 每批收尾时**回扫本表**（与"发布后同步四处"同级）。

**回勾纪律（规则②的补充，2026-09-27 加）**：**改动完成后必须在同一个提交里把本行改成 `已完成`**，
不要留给"下次收尾一起勾"。违反的实例：`node-repl-host/dist-types/` 那行在 `d7bf6ce` 里已被修好，
但该提交**没有改本表**（`git show d7bf6ce -- docs/development/backlog.md` 为空），于是它一直显示"已排入本版"——
**台账滞后与"真的没做"在表面上看不出区别**，这正是本表建立时要防的失效模式。
⇒ 判定某行是否真的完成时，**不要只看状态列**，用 `git log` / `git ls-files` / 源码反查。
