# 欠账台账（Backlog）

> **用途**：唯一汇总处。任何"未做 / 排后续 / 有意不做"的东西都记在这里 —— 否则它会散落在 release-notes、分析报告、清单、issue 里，**然后被漏掉**。
> **建立原因**：2026-09-24 汇总本批欠账时发现它们散落在**四处**（release-notes 的已知限制、`.reverse/90-upstream-v3143/` 的建议序、`.reverse/archive/45-release/CE3-CHECKLIST.md`、`.reverse/92-copy-format/`），**没有一处能看到全貌**。
> **完成项去哪了**：**完成的条目从本表删除**，登记到不追踪的交付日志（`.reverse/101-ce5-delivery/WORKLOG.md` 及后续同类文件）。本表只追踪**未完成**——留下的完成行是冗余信息。判定某项是否真的完成不靠本表，用 `git log` / `git ls-files` / 源码反查。

## 记录格式

| 字段 | 含义                                                        |
| ---- | ----------------------------------------------------------- |
| 条目 | 要做什么（一句话）                                          |
| 类   | `正确性/安全` / `上游跟进` / `协议引擎` / `产品面` / `工程` |
| 来源 | 结论出自哪份报告或哪次决策                                  |
| 代价 | S / M / L                                                   |
| 风险 | 低 / 中 / 高（含"不做会怎样"）                              |
| 状态 | `待排` / `已排入 <版本>` / `有意不做（原因）`               |

**规则**：① **有意不做**必须写原因（否则后人会以为是漏了）；② **完成即删除本行**并登记进交付日志（`.reverse/10x-*/WORKLOG.md`，不追踪不入库）；③ 每批收尾时**回扫本表**（与"发布后同步四处"同级）。
**判定完成的硬规矩**：状态列不算数。用 `git log` / `git ls-files` / 源码反查（本表历史上出现过"台账滞后"与"真的没做"表面无区别的失效模式，也出现过提交信息与 diff 矛盾的最难发现类——只看 diff，不看 commit message）。

**同批纪律**：改动的文件若落在 `third-party/inventory.json` 的 `inputs` 内（覆盖约 3000 个文件，含根 `package.json`、`pnpm-lock.yaml`、各 workspace `package.json`、插件 skill roots 内的技能正文与测试文件），**必须同一个提交跑 `node scripts/licenses.mjs notices`**。已固化护栏：`scripts/check-staged-licenses-inputs.mjs`（挂在 `.husky/pre-commit`，判暂存集 ∩ inputs；逃生阀 `SKIP_LICENSES_INPUTS_CHECK=1`）。**"我只改了注释 / Markdown / 测试"不构成跳过它的理由**。
