# live-config-watch

监听与读取原语：打开的会话重读配置时共用这一套，领域只写加载器。

当前状态：原语已在 `watched-source.ts` 实现，行为由 `test/watchedSource.test.ts` 钉住；尚未接入任何领域 ——
skill 实时目录、MCP 配置源、插件清单都还没有调用它，接线是后续任务。本目录以 `./watch` 子路径导出
（`src/watch/index.ts`，包级 `src/index.ts` 不转发），全仓目前只有测试引用它。

不变量：

- 加载器每次全量读取，并登记本次读到或依赖的文件（缺失的也登记）与只看直接子目录的目录；只有结果被采纳时才 commit。
- 锚点是已存在的最近目录，缺失时只在边界之内向上找；depth 0，不监听边界之外。
- 文件事件只使条目失效，300 ms 尾部去抖后串行重读；新绑定的 watcher 就绪后再读一次。不轮询，不用超时决定状态。
  唯一例外是监听建立：一次绑定（逐个锚点 stat 与等 watcher 就绪/报错）共用 1 秒总截止时间（`WATCH_BIND_TIMEOUT_MS`），
  超时的锚点即断路、停止监听并记一条 warn；配置内容仍只由全量读盘决定。
- 同一锚点、同一身份（`dev:ino`、覆盖文件、目录列表）的 watcher 失败两次即停止监听，记一条 warn；
  就绪前、就绪后的报错都计数。只有经历过一次读盘提交的 watcher 收到的文件事件才清零计数。
  身份变化或条目重建后重新尝试。停止监听不影响 flush：仍全量重读。
- 绑定超时断路：一次绑定内同一锚点只 stat 一次，共用它的多个目标复用同一结果；stat 超时的锚点以超时标记停止监听，
  之后的绑定不再 stat 它；watcher 未在截止时间前就绪或报错的锚点按当前身份停止监听；截止时间过后本轮还没处理的锚点，
  已在监听的保留原 watcher、下一轮照常 stat，其余直接断路。断路不调度重绑、不清零，状态跟条目走，条目重建后重新尝试。
- 同一进程内 key 相同的调用方共用一个条目；复用时先 flush；最后一个 view 释放时关闭 watcher。
- `createWatchedEntry(options, deps?)` 的第二个参数是系统边界（锚点 stat 与目录监听），生产调用不传；
  测试用它注入网络盘上的两种故障：stat 挂住、watcher 既不就绪也不报错。监听库只用 all / raw / ready / error 四个事件与 close。
